# first thoughts

walking into it i knew it was opinionated and thought from the get go that some things just wouldnt be how i would want them to be. but after ~1 week of using it i can say i was wrong.

## speed

 when my editor opens instantly, search feels instant, no useless UI animations, no lag, your brain is more incentivized to stay in the code instead of focusing on the constant distractions.

## collaboration

in my experience collaboration features, when i actually use them, in code editors always feel so lacking and i can never pin point where that feeling comes from. wether it is just a horrible flow, bad implementation, or just overall not done properly. zed on the otherhand hit the nail on the head in my opinion. it doesnt feel tacked on but rather built into it, all features work exactly as they should and it doesnt feel like a maze getting it started.

## AI

zed's recent direction is more interesting because it is not pretending there will only be one agent forever. the built-in agent exists, but zed also opened up external agents through acp, so the editor can act more like a good client than a locked platform.

that is the right idea.

i do not want my editor to marry one model vendor. i want a good interface for code review, codebase context, multi-file edits, and letting me swap the brain behind it when the market changes again next month.

## the "bad"

overall i dont have much criticism for zed itself but rather how it feels coming from something else. for instance if you rely on some niche extension for your whole workflow, zen wont have that, stick to your bearings. if you use vim zed can still feel very gui reliant.

the important part is that zed is now good enough that people are choosing it for what it is, not just for what it might become.
